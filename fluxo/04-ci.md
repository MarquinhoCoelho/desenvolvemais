# CI — verificações automáticas

A CI roda em **todo PR** e em **todo push na `main`**. Cada etapa é um "portão": se falhar, para tudo.

| Portão | O que confere | Exemplo Node | Exemplo Python |
|---|---|---|---|
| Instalação travada | dependências do lockfile | `npm ci` | `pip install -r requirements.txt` |
| Formatação | estilo igual em todo o código | `prettier --check .` | `black --check .` |
| Lint + complexidade | erros comuns, função ≤ 10 de complexidade | `eslint .` (regra `complexity: [error, 10]`) | `ruff check .` (regra `C901`, `max-complexity = 10`) |
| Tipos | sem erro de tipo | `tsc --noEmit` | `mypy .` |
| Testes + cobertura | tudo verde, cobertura ≥ mínimo | `jest --coverage` (`coverageThreshold`) | `pytest --cov --cov-fail-under=85` |
| Auditoria | sem vulnerabilidade alta conhecida | `npm audit --audit-level=high` | `pip-audit` |
| Padrão de commit (opcional) | mensagens no padrão | `commitlint` | `commitlint` |
| Build | o projeto compila / imagem sobe | `npm run build` | `docker build .` |

Modelos prontos: [templates/github/workflows/](../templates/github/workflows/).

## Regras

- **O mínimo de cobertura fica no arquivo de config do projeto** (`jest.config`, `pyproject.toml`),
  não só na CI. Assim o dev vê a mesma falha localmente.
- **Começar realista.** Projeto com 30% de cobertura não vai para 85% num dia. Gate = valor atual, e sobe aos poucos.
  Regra que sempre complementa: **código novo** precisa vir com teste (o revisor de qualidade confere).
- **Tudo que a CI roda, o dev consegue rodar local** com um comando (ex.: `npm run verificar`).
- Módulos opcionais (E2E, carga, segurança, revisão com Claude no PR) entram como jobs extras.
